## Fixes in this pass

1. **History status went stale for Workbench runs** (all platforms, found here).
   The run-end history refresh lived only in `ChatTab`, which is mounted only for
   the open project. A run started and watched from the Workbench never refreshed
   the cached `has_changes: false`, so a project's first change showed no
   changed-files line (and no 历史 glyph) until a reload. `noteAgentStatus()` in
   `hooks/useFileHistory.ts`, fed from App's global `agent.status` handler,
   re-reads the status when a run ends, only for projects this device already
   holds a status for. Two vitest cases (red first). Re-verified live: a
   Workbench-sent edit in a never-changed project shows 改了 1 个文件 with no reload.
2. **Windows test fixes (test-only, no product change):**
   - `test_history_service.py` / `test_history_routes.py`: write fixtures with
     `newline="\n"` (Windows text mode wrote CRLF, so byte and hash checks failed: 11 tests).
   - `test_history_service.py::test_max_wait_flushes_a_file_written_without_pause`:
     `xfail` on win32 — see limitation 1.
   - `test_chinese_session_ids_159.py`: the two POSIX `bg` runs skip on win32;
     `tests/platform/test_jobs_windows.py` gains the `bg.cmd` Chinese-session-id case.
   - `test_deferred_seed.py`: the fixture points `~` away from pytest's tmp dir
     (on Windows tmp sits under the real home, so the header showed `~\…`).
   - `test_calendar_routes.py`: read OpenAPI paths — FastAPI 0.162 keeps an
     included router as one nested `app.routes` entry (would fail on any fresh install).
   - `test_safari_upload_button.py`: read App.tsx as UTF-8 (the batch added non-ASCII text; cp1252 decode failed).

## Known limitations / not this batch

1. **watchdog 7 on Windows holds events while a file keeps changing.** A file
   written every 100 ms for 6 s produced no events until ~0.9 s after the last
   write (then all 60 at once). So the 60 s `max_wait` guarantee does not hold on
   Windows: a continuously appended file (a live log) gets its version when
   writing pauses or at the 10-minute reconcile. A stat-poll fallback would be a
   product decision.
2. **Codex CLI 0.162.1 (pinned 0.157.1):** the transport's default model fell back
   to `gpt-5.5`, which this ChatGPT-account Codex rejects (`model_not_found`);
   picking a model in the pin menu worked. Codex's sandbox now denies WMI
   (`Invoke-CimMethod : 拒绝访问`) so `bg.ps1` fails inside it; Codex escalated and
   the escalated command ran without the `ORBITAL_*` env, so that job was
   untracked. Batch 1026's D7 passed on 0.157.1. Pre-existing, not batch 1104.
3. `bg.cmd` still drops quotes when the command is not passed as one quoted
   argument (documented D9 limit).
